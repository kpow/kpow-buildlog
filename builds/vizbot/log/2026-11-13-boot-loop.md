On protocol v2 the StackChan fell into a boot loop. Every boot downloaded the same 43 KB of cloud content and crashed again.

The cause was the voice wake stream: 1 KB of mic audio over UDP every 32 ms, plus a 32-chunk pre-roll sent back to back. It filled the WiFi TX buffers, so the TLS download and the next connects failed with ENOMEM.

- **Network hold:** the wake stream and WLED fade frames pause for each cloud request and while the answer is applied.
- **Back-off:** after 3 failed wake sends in a row it pauses 1 to 8 s instead of retrying every chunk. The pre-roll is paced.
- **PSRAM:** ArduinoJson had put every cloud document and all cached content in internal RAM. It now uses a PSRAM allocator.
- **Crash guard:** a boot after a panic or watchdog reset skips the content version it crashed on for an hour and reports it, and VizCloud flags it on the bot's page.

> **Trap:** the WiFi stack has only 8 static TX buffers. A steady UDP stream can hold all of them, and a TLS download started alongside it fails with ENOMEM.
