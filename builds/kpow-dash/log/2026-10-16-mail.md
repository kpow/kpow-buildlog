Clicking a row used to throw me at Gmail. Now the conversation opens in place. j and k
walk every thread both accounts are showing, r replies, e marks read and moves on, #
trashes and moves on, esc backs out. The queue freezes when it opens, so trashing
something never reshuffles the list under my fingers mid-triage.

Replies are plain text to the sender only, threaded properly with In-Reply-To and
References, with the original quoted underneath. Sending drops UNREAD, because
answering something means I dealt with it. No reply-all, no attachments, no pretending
to be Gmail.

The reading side is the careful part. The server walks the MIME tree, strips scripts,
iframes, objects, inline handlers and `javascript:` urls, and parks every remote image
on a blocked attribute with a count. The client renders that in an iframe with no
`allow-same-origin` and a CSP of `default-src 'none'`, which is the actual boundary;
the scrub is the second layer.

Three things the real inbox corrected about the plan:

- Half of it has no text/plain part at all, so the sandboxed HTML render was required,
  not a nicety for later.
- Blocking images is not caution. The first newsletter tested carried 22, and the first
  of those was an open-tracking beacon addressed to the account that received it.
- `cid:` images are inline attachments, usually an Outlook signature logo, and the
  iframe cannot resolve them, so those tags get dropped rather than left as broken
  boxes.

Around it, the lists grew a checkbox per row and a toolbar per account with select-all,
mark read and trash in bulk, and a divider between sender and subject that drags to
resize both lists.

> **Note:** sending has not been tried against a real recipient yet, and the Gmail API
> has no unsend, so the first one is worth doing deliberately.
